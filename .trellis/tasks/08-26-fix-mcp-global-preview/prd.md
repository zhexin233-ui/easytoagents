# 修复 MCP 全局预览并补齐原生导入

## Goal

让用户把 Claude Code / Codex 已有的全局 MCP 明确导入应用中央库，随后正常生成同步预览；消除“工具已有 MCP，但页面只提示没有待写入项”的操作断点。

## Background

- 用户反馈：两个工具均配置了全局 MCP，点击“生成全局预览”却得到“当前没有需要写入全局配置的 MCP”。
- 用户已同意创建任务，并于后续回复“可以”确认补齐原生 MCP 导入能力；已在最终方案摘要后明确回复“可以”，批准进入实施。
- 2026-08-26 本机只读核验：Claude `mcpServers` 有 3 项，Codex `mcp_servers` 有 6 项；应用中央 `mcp_servers`、全局分配、MCP 受管目标均为 0。两个工具有 3 个同名项；Codex 有 1 个明确停用项。仅记录数量与结构信息，未输出配置值或凭证（`research/local-state.md`）。
- 页面仅依据 `PreviewPlan.targets.length === 0` 显示空提示（`src/features/mcp/mcp-page.tsx:175-180`）。后端候选来自中央全局分配且只取启用项（`src-tauri/src/db/mcp.rs:355-390`、`src-tauri/src/mcp/service.rs:423-449`），不从原生文件自动入库。
- 现有 MCP 页面只有手工创建和分配入口（`src/features/mcp/mcp-page.tsx:437-524`）；上一次初始化状态修复没有增加原生导入（`research/frontend-preview.md`、`research/backend-preview.md`）。
- 既有设计禁止未经确认接管外部内容，并要求原生写入单独走 Preview/Apply（`.trellis/tasks/archive/2026-08/08-19-ai-config-desktop/design.md:5`、`.trellis/tasks/archive/2026-08/08-19-ai-config-desktop/prd.md:66`）。

## Requirements

- **R1 · 发现入口**：MCP 页面提供按 Claude / Codex 触发的“检测并导入已有 MCP”入口。展示来源路径、候选名称、协议、可导入状态及原因；区分扫描中、无配置、无可导入项、读取失败和策略阻止。
- **R2 · 显式导入**：候选由用户勾选并确认。只把所选项新增或复用为中央记录，并建立来源工具的全局分配及对应管理关系；不得自动分配给另一工具、自动勾选全部条目或自动 Apply。
- **R3 · 保持原配置**：发现、确认导入和生成预览均不改写原生文件。未选中项保持非受管；已导入项随后可生成非空同步预览，不因缺失所有权证据而被误判为外部同名冲突。必要的格式规范化变化仍通过后续同步预览展示。
- **R4 · 同名处理**：原生名称精确相同、规范化配置（含私有敏感值及扩展字段）完全一致时，确认界面明确说明复用中央记录并添加来源工具分配。配置不同或仅大小写相同的条目显示冲突，不覆盖、不自动重命名；不能仅按名称或脱敏后的值判断等价。
- **R5 · 分批与重复导入**：支持先导入部分、再次扫描后导入剩余项；已管理项显示为已导入且不能重复接管。重复提交同一确认不会重复创建记录。原有受管内容发生漂移时不得借新导入重设旧基线。
- **R6 · 格式边界**：本次可选择导入符合现有中央模型的已启用 `stdio` / `streamable_http` 项，保留可表达的扩展字段与敏感值。停用项、SSE、不能保真表达的引用字段或非法条目仍展示原因，但不可选择并保持原配置不变；一个条目不可导入不妨碍其余合法条目。尤其不得将 Codex `enabled=false` 自动启用，或接管后在下一次同步中删除。
- **R7 · 安全与一致性**：确认必须验证扫描令牌、来源身份、文件状态、中央记录及已有管理状态没有过期，按单个来源工具原子完成所选项导入；失败时不留下部分记录或分配。路径、版本能力、策略、进行中写入和既有项目分配约束继续生效。敏感值只在后端私有存储中保留，RPC、导入预览、日志、错误和同步记录必须脱敏。
- **R8 · 清晰下一步**：中央库为空及全局同步预览无目标时，说明“暂无启用且已分配到该工具的中央 MCP”，并指向导入或创建/分配操作，不暗示工具原生配置不存在。导入成功明确提示原生配置未改写，并引导单独生成全局预览；空预览仍不打开 Apply 对话框。
- **R9 · 验证**：前后端补齐本流程和安全边界回归，沿用隔离临时目录、生成绑定与现有测试体系，不对真实用户配置执行导入确认、Apply 或写入测试。

## Acceptance Criteria

- [x] **AC1（R1、R8）**：两工具原生有配置、中央库为空时，用户可从 MCP 页面进入按工具扫描，看到准确候选和可执行下一步；不存在配置和扫描失败不会混为一类。
- [x] **AC2（R2、R3）**：只勾选一部分并确认后，只有这些条目进入中央记录/来源工具全局分配/管理关系；确认前后原生文件字节不变，未选中项不被接管。
- [x] **AC3（R3）**：导入后生成来源工具的全局同步预览，目标非空且无虚假的外部同名冲突；后续在隔离 fixture 中 Apply 时保留未选中条目和无关字段。
- [x] **AC4（R4）**：两工具同名同配置条目复用同一中央记录并分别具有全局分配；同名不同配置、大小写冲突均明确阻止该项且不修改现有中央/原生值。
- [x] **AC5（R5）**：再次扫描可导入剩余项；已管理项不可重复选择；重复确认不会重复创建，旧管理内容漂移或缺失时不能通过导入覆盖基线。
- [x] **AC6（R6）**：停用、SSE、不支持字段和非法条目均有逐项原因，不阻断其它合法候选；停用项不启用、不接管、不在后续同步中被删除。
- [x] **AC7（R7）**：扫描后文件、路径、相关中央行版本或管理状态变化时确认失败并要求重新检测；伪造/空/重复选择、过期令牌、同名冲突、项目分配冲突均无部分入库。
- [x] **AC8（R7）**：未知能力/策略、非法 JSON/TOML、不可读或不安全路径、活动 Apply/Restore 被保守处理，不发生原生写入或绕过现有保护。
- [x] **AC9（R7、R9）**：fixture header/env/扩展密钥及被拒绝的敏感参数不出现在实际 RPC、导入预览存储、错误、同步预览和 journal 中；确认后私有中央配置仍完整保留允许导入的敏感值。
- [x] **AC10（R1、R2、R8）**：导入界面具备加载/错误/空/成功反馈及无障碍关闭、焦点行为；确认只提交令牌和所选候选 ID，不调用手工创建或 Apply；关闭重开后不会复用旧选择或旧扫描。
- [x] **AC11（R8、R9）**：真正没有全局候选、仅项目继承、全局启停与现有冲突场景不回退；生成绑定和前后端质量检查通过。

## Out of Scope

- 自动扫描即接管、自动 Apply、开发期间改写本机 Claude/Codex 配置。
- 项目级原生 MCP 导入、跨两个工具的一次性批量事务、市场或远程 MCP 安装。
- 自动覆盖同名冲突、自动重命名、交互式冲突合并编辑器。
- 扩展中央模型来管理原生停用状态、SSE 或 `env_http_headers` 等目前无法保真表示的字段；这些项显示原因并保持外部原状。
- 改造 Provider/Prompt 导入机制、Skills 功能或通用同步引擎架构。
