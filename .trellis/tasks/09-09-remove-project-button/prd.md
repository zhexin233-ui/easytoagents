# 新增移除项目按钮

## Goal

让用户能直接从左侧项目列表清楚、安全地移除项目登记，而不必先进入项目页，也不删除项目目录或改写已有原生配置。

## Background

- 项目卡片当前已有“移除登记”按钮，直接调用既有软移除命令：`src/features/projects/projects-page.tsx:53-69,233-245`。
- 左侧项目导航当前只有详情链接，没有项目操作入口：`src/app/app-shell.tsx:174-261`。
- 后端移除语义已经存在：隐藏项目登记、清理项目级 MCP/Skill 分配，并保留项目目录、原生配置、同步历史和恢复证据。
- 有已禁用或冲突的原生资源时，现有前后端都会阻止移除。

## Requirements

- 左侧项目列表的每个项目行末尾新增图标按钮，按钮的可访问名称和 `title` 必须包含“移除项目”及项目名称。
- 保留项目卡片当前的“移除登记”按钮，不改变既有入口。
- 点击侧栏移除按钮不得触发所在行的详情导航；提交前必须二次确认，并明确展示项目名称以及“只移除登记、不删除项目目录或原生配置”的语义。
- 复用现有 `commands.removeProject({ id, rowVersion })`，不新增物理删除项目文件或目录的能力。
- 移除成功后刷新项目、MCP 和 Skill 相关查询，使项目从所有已登记项目入口消失。
- 若移除的是当前正在查看的项目，成功后导航到项目列表；移除其他项目时保留当前路由。
- 移除成功或失败时通过现有可访问通知组件给出结果；失败时保留当前项目与操作入口，并展示结构化错误。
- 阻塞状态必须语义化禁用，并以可见文字解释原因。
- 确认期间禁用所有侧栏移除按钮，防止重复或并行提交。

## Acceptance Criteria

- [x] 每个侧栏项目行均显示可聚焦、可识别具体项目的移除按钮，项目名称链接仍能正常导航。
- [x] 取消二次确认时不调用移除命令；确认文案明确说明保留项目目录和原生配置。
- [x] 发起移除时使用所显示项目的精确 `id` 与 `rowVersion`。
- [x] 成功后项目从项目列表及侧栏消失，并明确提示项目目录和原生配置未被删除。
- [x] 移除当前项目后进入项目列表，移除非当前项目时不改变当前页面。
- [x] 有已禁用或冲突原生资源的项目无法发起移除，且用户能看到原因。
- [x] 确认期间不能重复或并行提交。
- [x] 命令失败时显示可访问的错误状态，项目仍保留在界面中。
- [x] 自动化测试覆盖侧栏入口、确认、取消、精确 payload、阻塞状态、路由行为和成功后的查询刷新。

## Out of Scope

- 删除项目目录或其中任何文件。
- 删除已有原生配置、同步历史或恢复证据。
- 修改后端软移除合同或新增恢复已移除项目的界面。
