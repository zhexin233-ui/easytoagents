# 修复全局 Skills 检测、导入与初始状态提示

## 目标与用户价值

让用户在 Skills 页面发现已经安装的 Claude/Codex 全局技能，显式选择后导入中央库；准确解释尚未由 EasyToAgents 管理的内容，避免把首次发现误报为用户修改。

用户已在最终规划摘要后回复“可以”，批准按本方案实现。允许修改产品代码并使用隔离 fixture 验证，不对真实全局技能目录执行导入或同步。

## 背景与证据

- 中央列表只从数据库读取，不会发现原生目录中的技能：`src-tauri/src/skills/service.rs:48`。
- 当前本地导入仅接受单个包含 `SKILL.md` 的目录：`src/features/skills/skills-page.tsx:222`、`src-tauri/src/skills/service.rs:60`。
- Codex 全局同步目标为 `HOME/.agents/skills`；现有 `HOME/.codex/skills` 不在该发现链路内：`src-tauri/src/adapters/codex/mod.rs:101`。
- 目录存在、两个管理基线 hash 都为空且受管投影为空，也会被归类为 `external_non_owned_change`：`src-tauri/src/sync/mod.rs:408`。该提示不能说明原有技能无效；只有一个 hash 的不完整基线仍属于冲突。
- Skills 全局目标卡片只有同步预览，没有检测或导入已有技能的入口：`src/features/skills/skills-page.tsx:385`。
- 本机只读布局核验：Claude 有两个指向 `.skills-manager/skills` 的技能链接；Codex `.codex/skills` 有三个普通入口和 `.system` 内置集合，`.agents/skills` 不存在。详情见 `research/source-layout.md`；这里只验证目录形态，未读取真实技能正文或执行脚本。
- 单目录导入当前拒绝入口根链接：`src-tauri/src/skills/library.rs:402-414`。分配同名中央技能后，原有普通目录/外部链接仍会触发同步冲突：`src-tauri/src/skills/service.rs:1533-1603`。

## 需求

| ID  | 需求                                                                                                                                                                                                      |
| --- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| R1  | 提供显式检测现有全局技能的入口，覆盖解析后的 Claude 配置根 `skills`、Codex `HOME/.agents/skills` 与解析后的 `CODEX_HOME/skills`（默认 `.codex/skills`）来源；可重新检测。新增导入来源不改变官方同步目标。 |
| R2  | 展示候选名称、来源和可导入状态；用户选择后才导入，未选择内容不受影响。                                                                                                                                    |
| R3  | 支持安全读取指向技能目录的符号链接；断链、无效内容和权限问题有明确反馈，不能简单当作没有技能。                                                                                                            |
| R4  | 沿用中央副本模型，不删除、覆盖或替换原有技能目录或链接，不自动创建来源工具分配或接管基线；原生同步仍须独立预览和确认。导入成功说明原安装未变、中央副本不会随原安装自动更新。                              |
| R5  | 区分首次发现的外部内容与已管理目标发生的真实变更；空目录不能声称发现了技能，单纯复制到中央库也不能显示原目录已受管。保留真实冲突与策略阻断提示。                                                          |
| R6  | 导入结果及时反映在中央列表；精确同名且完整内容相同、中央副本仍有效时识别为已导入并复用已有记录，不产生额外副本或分配。名称仅大小写相同或内容不同则提示冲突，不静默覆盖或改名。                            |
| R7  | 检测后选中项的来源链接、目录内容或相关中央记录发生变化时，确认必须拒绝过期选择并要求重扫；失败不能留下可见的部分中央记录或改变原目录。扫描与确认有明确资源上限，达到上限不得伪装为完整成功。              |
| R8  | 用户已确认内置技能不在本次导入范围。排除 Codex `.system` 内置集合，不生成其技能候选、不递归读取其正文；可以展示该来源被排除的说明。                                                                       |

## 验收条件

- [x] AC1（R1、R2）：中央列表为空时，也能检测已有 Claude/Codex 全局技能并选择导入。
- [x] AC2（R1）：只有 `.codex/skills` 存在时仍能发现 Codex 技能，不要求先创建 `.agents/skills`。
- [x] AC3（R2、R4）：只导入勾选项，检测与导入不改变原目录中的文件和链接。
- [x] AC4（R3）：有效的技能目录链接可被处理；断链、无权限、无效技能可识别且不会被执行。
- [x] AC5（R5）：没有管理基线的已有内容使用首次发现提示；真正的受管变更、冲突和阻断继续正确展示。
- [x] AC6（R2、R6、R7）：重复/冲突候选可区分；无默认勾选、失败/超限反馈、重扫、确认期间防重操作、焦点与列表刷新有回归覆盖。
- [x] AC7（R4、R7）：导入不会自动开启全局分配或消除同名外部占用；确认遇到来源/中央版本变化或重复令牌时，不产生部分成功或额外副本。
- [x] AC8（R1）：自定义配置根与默认根使用同一显式发现规则；多个入口指向同一技能时可识别重复，不产生无提示的重复导入。
- [x] AC9（R8）：`.system` 内置技能不出现在可选候选中；仅有内置技能的目录显示“没有可导入的用户技能”，不会导入内置内容。

## 不在本次范围

- 技能市场、网络下载、插件安装或执行技能正文/脚本。
- 自动写入 Claude/Codex 原目录、静默覆盖同名技能或绕过同步预览。
- 扩展项目级技能发现、批量修改现有项目或更改其他功能的漂移规则。
- 自动接管/迁移原有技能安装、跟随其他技能管理器更新中央副本、任意目录递归搜索或新增搜索根配置。
- 内置技能导入，以及主动遍历插件缓存寻找技能。

## 决策、风险与审阅状态

- 用户已明确：“内置技能不纳入本次导入范围”。该产品范围已收敛。
- 沿用既有产品的中央副本合同。原安装不会自动跟随中央副本变化；导入不消除同名外部占用。用户以后主动选择同步时仍需独立处理冲突。
- 来源链接在检测到确认之间可能变化；必须重新验证，不能按上一次解析路径盲目复制。正常失败保证数据库批次不部分可见，但文件系统与 SQLite 不具备跨资源原子性；崩溃可能留下私有无记录副本，不能猜测删除。
- 技术合同、迁移兼容和失败边界见 `design.md`；执行顺序、质量门禁与 AC1–AC9 验证见 `implement.md`。证据见 `research/import-safety.md`、`research/source-layout.md`、`research/status-and-ui.md`。
- 本任务是一个完整的检测→选择→中央导入交付，不拆分独立产品子任务。规划材料和上下文清单已完成，用户已在最终摘要后明确批准实现；任何实质范围变化仍须重新审阅。
