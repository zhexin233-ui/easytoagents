# 全局 Skills 检测与导入：技术设计

## 1. 边界与不变量

本任务填补全局用户技能到中央库之间的入口，不改变 Skills 的中央副本模型，不增加原安装接管能力。用户已明确排除内置技能。

- Rust 负责显式来源、目录读取、校验、复制、哈希和事务；React 只消费生成 DTO 并提交候选选择。
- 检测不创建中央目录、技能记录、分配或受管基线；允许持久化私有导入证据。
- 确认只复制用户选择的技能到应用私有中央库。原目录、链接及其目标的字节和权限保持不变。
- 不创建全局/项目 assignment，不记录原安装的 managed ownership，不调用 Apply。现有外部同名冲突保护继续有效。
- 不执行 SKILL.md 中的指令、技能脚本或包管理命令；正文不进入普通候选 DTO、导入证据或日志。
- `.system` 不展开、不生成技能候选；不新增插件缓存扫描。实现过程与测试均使用隔离来源，不对用户真实目录执行导入或同步。

## 2. 来源解析与枚举

### 2.1 来源矩阵

| 工具   | 检测来源                                                                               | 正式同步目标               |
| ------ | -------------------------------------------------------------------------------------- | -------------------------- |
| Claude | `ExplicitEnvironment.claude_config_dir()/skills`                                       | 同一解析后的 Claude 路径   |
| Codex  | `ExplicitEnvironment.home()/.agents/skills`、`ExplicitEnvironment.codex_home()/skills` | 仍为 `HOME/.agents/skills` |

默认 Codex 兼容来源是 `HOME/.codex/skills`；非默认 `CODEX_HOME` 的技能目录只作为导入来源，不改变 adapter 的同步目标。来源由后端显式环境生成，不接受前端任意路径，不在服务中重读进程环境。命令沿用既有工具能力/策略证据；未知、阻止或无法安全定位时不能生成可确认的候选。

每次只检测用户指定的一个工具，Codex 的两处来源在同一对话框显示。某个来源缺失/空/不可读须独立显示，不能使另一个有效来源消失，也不能把错误伪装为没有技能。工具级策略阻断仍优先于候选导入。

### 2.2 枚举范围

1. 对可信根做有界的直属孩子枚举。普通文件（如 `.DS_Store`）不是候选；目录或目录链接必须自身包含普通文件 `SKILL.md`。
2. 不递归寻找任意集合中的技能；不把子目录里偶然出现的 SKILL.md 当作新的顶级候选。技能本身的资源树仍按现有安全规则递归验证。
3. 在打开技能正文之前排除 Codex `.system` 集合；显式入口链接最终解析到已知 `.system` 树内也排除，不能通过换名链接绕过范围。仅给出“内置技能不在本次导入范围”的来源说明。
4. 以稳定路径顺序枚举，设置独立常量：最多 256 个候选入口、每次确认最多 32 个合并后的候选、一次检测/确认累计最多读取或复制 128 MiB；单技能仍受现有文件数、深度、文件大小和总大小限制。超过预算显示明确诊断，不静默声称扫描完整。
5. 同一真实目录的多个入口合并并保留全部来源路径；精确名称和完整树哈希相同的多个来源可合并为一个候选。相同名称但不同内容、NOCASE 名称碰撞均明确冲突，不由遍历顺序选择胜者。

### 2.3 来源入口链接

现有 `prepare_skill_import` 默认拒绝根链接，这一入口的默认合同保留。新建仅供显式全局发现使用的来源解析边界：

- 只允许已枚举的直属入口作为链接解析起点，有限解析相对或绝对链接，最多 32 跳并检测循环。每一跳的父路径必须可通过已有 no-follow/身份检查证明安全；不自动允许任意祖先链接。
- 绑定来源根、原入口、每段显式链接文本/身份和最终真实目录身份；最终目录须通过既有来源目录验证，不能是广泛根、特殊文件或未知应用私有目录。
- 以已打开的真实目录描述符为后续读取边界；检测结束、确认、复制前后重验来源链及真实目录。不能仅以一次 `canonicalize` 和后续普通路径读取代替证据。
- 内部资源链接仍沿用现有规则：仅允许目录内的安全普通文件链接，拒绝逃逸、断裂、循环、目录链接、硬链接和特殊文件。`SKILL.md` 必须是普通有界 UTF-8 文件。
- 已指向应用中央库的入口只能在证明中央记录 ID/path/hash 一致后标记“已在中央库”；未知私有路径拒绝，禁止再次复制中央目录到自身。

只读 inspect 和复制复用 `library.rs` 的扫描/hash/frontmatter 逻辑，提取窄内部 helper，不复制另一套技能解析器。Skill 校验规则本次不放宽；已有不兼容技能须有明确理由，不能为了扫描成功吞掉校验错误。

## 3. 候选与跨层合同

新增窄命令，Rust/Specta 是唯一类型来源：

- `discover_skill_import(tool: Tool) -> Result<SkillImportPreviewDto, AppError>`。
- `confirm_skill_import(input: ConfirmSkillImportInput) -> Result<SkillImportResultDto, AppError>`。
- 输入只有 `previewId` 和非空、不重复的 `candidateIds`；工具、路径、名称、哈希、中央 ID 均从后端证据解析。

`SkillImportPreviewDto` 包含 `previewId: string | null`、`tool`、`sources`、`candidates` 和安全说明。没有可新建候选时不返回可确认令牌。

来源项包含来源类型（Claude 全局、Codex 用户目录、Codex 兼容目录）、路径、状态（ready/missing/empty/unavailable）及固定诊断；内置排除和预算截断以明确说明表示。不能把 ready 等同于已经同步。

候选项包含不透明 `candidateId`、安全名称/说明、来源路径集合、状态、固定原因及可选 `existingSkillId`。普通 DTO 不含任意 frontmatter、完整正文或原始解析错误。

| 候选状态           | 含义与行为                                                                                         |
| ------------------ | -------------------------------------------------------------------------------------------------- |
| `importable`       | 验证通过、中央不存在同名项，可选并创建一个中央副本                                                 |
| `already_imported` | 精确名称与完整树哈希相同，且中央记录/目录经重新检查有效；只读展示已有记录，不新增副本或 assignment |
| `name_conflict`    | 同名不同内容、仅大小写同名、同批来源碰撞；不可选，不覆盖、不改名                                   |
| `invalid`          | 元数据/内容/路径/链接/权限或预算不满足；不可选并展示静态原因                                       |

完整树哈希包含路径、文件内容、链接文本和规范化可执行位；不能只比较 SKILL.md 或显示名称。跨工具重复检测也按中央库记录归并，不绑定来源工具分配。

确认结果仅需 `tool` 和 `createdCount`；成功后前端重新查询中央列表。无需 MCP 的 `assignedCount` 或复用动作：本次“复用”是识别已存在并避免重复复制，不产生新管理关系。

## 4. 导入证据、批量确认与失败边界

### 4.1 私有证据

新增前向迁移 `0006_skill_import_previews.sql`，由 `db/mod.rs` 注册；不改历史迁移或借用 MCP/Profile 专用表。表保存 UUID、工具、版本化的 object-shaped `context_json`、安全展示 JSON、`previewed/consumed` 状态和时间；字段 CHECK/索引沿用现有导入表风格。

证据保存显式来源环境/能力策略指纹、候选 ID 到来源链/目录身份/完整内容哈希的映射、相关中央身份版本或不存在断言。必要时使用全部中央 Skill ID/row_version 的保守指纹；无关中央修改可能要求重扫，可接受但不能隐藏。

不保存正文、任意 frontmatter、原始错误或未选择技能的中央副本。来源显示路径与 canonical 路径分开：预览展示用户看到的入口，中央 `source_path` 沿用真实来源溯源合同，原入口证据保留在导入记录内。

### 4.2 确认顺序

1. 验证令牌状态、工具、证据版本和选择集合；拒绝未知、重复、不可选 ID 或超限批次。
2. 重新从显式环境定位来源，复核能力/策略、选中项的来源链和目录身份/内容哈希、中央指纹。未选中的技能不复制；不要求扫描到的其它不可读来源变为可读。
3. 为每个新技能复用既有 `prepare_skill_import` 生成本次专有 staging，确保所得名称/hash 等于令牌证据。重新校验来源入口，防止解析后入口被换成别处。
4. 在单个 SQLite `IMMEDIATE` 事务中重新读取令牌/中央版本，拒绝 `applying/restoring/rollback_failed` 写入。多实例即使各自准备了 staging，也至多一个能消费该令牌。
5. 事务内重新核验选中来源；把每个 staging 原子 finalize 为正式中央子目录，并插入全部技能记录。提取可在外部事务中调用的窄插入 helper，保留当前单目录 `insert_skill` 的事务包装；禁止循环调用各自 commit 的旧导入 API。
6. 提交前再检查来源证据和正式副本完整性，条件消费令牌并提交。同批记录和令牌消费要么一起可见，要么一起回滚。
7. 返回结果；原生目录、分配、受管基线和同步历史均不变化。

### 4.3 补偿与崩溃说明

- 发生可确定的提交前失败，事务回滚，清理本次创建的 staging/正式子目录；不得清理既有中央副本。清理须证明 ID/直接父目录/身份/hash 属于本操作，不能仅按目录名字递归删除已被替换的目录。
- 提交返回不确定结果时，不得盲目删正式目录。通过重新读取令牌状态和整批记录/路径/hash确认结果：已提交保留；确认未提交才清理；无法判定则保留私有证据并报告失败/待恢复，不宣称成功。
- SQLite 与文件系统不是跨资源原子事务。进程在 finalize 后、DB commit 前崩溃可能留下没有记录的私有副本；它们不显示为中央技能，不触碰原生来源。本次不增加自动垃圾清扫，重启/人工处理也不能猜测删除未知目录。
- 所有路径、错误和证据遵守现有权限及脱敏合同，目录 `0700`、文件 `0600` 加规范化所有者执行位。新增批量失败注入覆盖第二项复制/rename/SQL/提交边界。

## 5. 全局状态语义

保留通用 `SyncStatus`、`assess_drift` 和 MCP 状态语义。只在 Skills 状态服务中，已有判定允许且有充分原始证据时补充诊断码：

- `assessment.status == external_non_owned_change`；
- baseline 的两个 hash 同时为空；
- 既有 managed items 为空，且当前没有全局 desired assignment；
- scan 是成功的 `ObservedDocument::SymlinkDirectory`。

判断不依赖 `managed_targets` 行是否存在，因为仅生成预览也可能留下无基线的行。半个基线、有 managed items、中央技能损坏、策略/权限/类型问题均不得进入首次提示。

| 状态证据                                    | Skills 诊断/展示                                                              |
| ------------------------------------------- | ----------------------------------------------------------------------------- |
| 原目标缺失                                  | 保持 missing / “待初始化”                                                     |
| 满足上述条件且目录条目为空                  | `SKILL_TARGET_INITIAL_EMPTY` / “空目录，待配置”                               |
| 满足上述条件且有目录条目                    | `SKILL_TARGET_INITIAL_UNMANAGED` / “未纳入同步管理”；提示可检测其中的用户技能 |
| 已有完整基线，只有非受管内容变化            | 保持 `EXTERNAL_NON_OWNED_CHANGE` / “非受管变更”                               |
| 受管漂移、中央副本损坏、冲突、策略/权限阻断 | 保留现有状态、诊断和阻断                                                      |

状态扫描只有目录条目证据，不能声称已验证出合法技能，也不能把 `.DS_Store` 或内置集合算作用户技能。实际“发现多少、已导入多少”以显式检测结果为准。复制导入后目录仍可能显示未纳入同步管理，这是符合边界的状态。

`globalTargetStatusPresentation` 统一解释这两个 Skills 专用诊断；只在 `status` 与诊断都匹配时覆盖文案。MCP 不产生这些诊断，现有徽章默认行为和所有预览阻断规则不改。不为纯展示修改通用枚举或持久化漂移状态。

## 6. 前端交互与缓存

- 每个全局目标卡片增加“检测并导入已有 Skills”；中央空状态明确指向该入口，同时保留单目录导入。Codex 正式目标缺失不禁用对兼容来源的检测。
- 使用独立 `SkillImportDialog`，复用 Button、共享焦点 hook、错误格式化和既有模态布局，不耦合 MCP 的业务 DTO。
- 每次显式打开/重扫生成新 requestId，query key 为 `['skill-import', tool, requestId]`；`retry:false`、`staleTime:Infinity`、`gcTime:0`，禁用 focus/reconnect 自动重扫。关闭/换工具清空选择，旧响应不能打开或覆盖新对话框。
- 默认不勾选，只有 `importable` 可选。完整展示来源缺失、空、局部失败、非法/同名冲突、已在中央库和内置排除。没有可选候选时禁用确认，不显示误导性的总成功。
- 确认中同步防重提交，锁定关闭/取消/重扫，焦点留在弹窗容器；失败保留错误并要求重新检测后再确认，不能自动循环重试令牌。
- 成功失效 `skillKeys.all`，等待中央列表刷新，关闭对话框并恢复触发元素焦点。成功提示“已复制到中央库；原有安装未变，尚未自动分配或同步”。不失效旧 import key 触发隐式重扫，不调用 assignment/preview/Apply。
- 原生同步按钮保持既有行为；若用户之后主动分配到一个有同名外部安装的工具，仍须说明并保留原有冲突。

## 7. 兼容、影响与验证

主要影响：新增 `skills/import.rs`、`db/skill_imports.rs` 和迁移；调整 `skills/{library,models,service,mod}.rs`、`db/{skills,mod}.rs`、commands 注册/生成绑定；前端调整 Skills 页面/API、增加导入对话框并扩展共享状态展示。

既有单目录导入、全局/项目分配、项目继承、技能删除、MCP 导入及外部同步器保持合同。只对可复用的私有扫描/事务 helper 做小范围提取；不重构通用 Apply 引擎。

验证优先扩展已有 library/service/DB/page 测试，新增模块自己的测试仅用于新的来源证据逻辑。覆盖源路径矩阵、内置排除、目录链接身份变化、内部链接拒绝、hash/中央重复冲突、批量补偿、令牌重用、独立连接并发、原生文件/权限不变，以及完整初始/真实漂移 UI 矩阵。完整命令和检查点见 `implement.md`。

数据库升级从 v5 到 v6 并验证重复打开；旧二进制遇到新迁移不得假装兼容。回退需要兼容版本或迁移前私有备份，不自动降级/删表/改真实数据库。若实现发现必须改变接管、内置范围或来源安全边界，返回规划并重新审阅。
