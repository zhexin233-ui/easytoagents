# Claude 与 Codex 配置管理桌面端

## Goal

构建一个本地优先的 macOS 桌面端配置中心，让用户在一个界面中管理 Claude Code 与 Codex 的 Provider 渠道、全局提示词、MCP 和 Skills，并为不同项目追加项目专用的 MCP 与 Skills。

产品价值：减少手工编辑 JSON、TOML、Markdown 和 Skills 目录造成的切换成本、配置漂移、误覆盖与不可恢复修改。

## Background

- 当前仓库没有产品代码，本任务从零创建应用。
- MVP 仅支持 macOS 13 及以上版本、Claude Code 与 Codex；不承诺 Windows/Linux 兼容性。
- 配置路径和加载规则以 2026-08-19 核验的官方文档为准，见 `research/official-config-paths.md`。
- `coulsontl/ai-toolbox` 与 `xingkongliang/skills-manager` 只作为产品与架构参考，见 `research/reference-projects.md`。
- 应用本地数据库与中央 Skill 库保存用户意图；Claude/Codex 的原生配置文件和 Skills 目录是受控同步目标，而不是唯一真源。

## Requirements

### R1. Provider 渠道

- Claude 与 Codex 分别维护独立的命名 Provider 档案；一个档案只属于一个工具，每个已接管工具同时最多一份档案生效。
- 档案包含 API 地址、明文 API Key、默认模型及工具所需的相关配置字段。
- Claude 渠道应用到 `$CLAUDE_CONFIG_DIR/settings.json`（默认 `~/.claude/settings.json`）的受管 `env` 项，包括 API 地址、认证值、模型和档案声明的相关变量。
- Codex 渠道应用到 `$CODEX_HOME/config.toml`，默认路径为 `~/.codex/config.toml`；直接密钥通过官方仍支持但明确不推荐的 `experimental_bearer_token` 写入。
- 用户可以新建、编辑、重命名、删除、复制到另一工具并切换档案；复制后是独立记录，必须按目标工具重新校验。
- 首次发现已有 Provider 配置时先展示并允许导入为当前档案，未经确认不得接管。
- 切换只修改应用拥有的 Provider 字段，清理上一个档案遗留但新档案不再需要的受管字段，保留 MCP、插件及其他用户配置。
- MVP 不启动代理、中转、端口监听或常驻后台服务。

### R2. 全局提示词

- Claude 与 Codex 分别维护独立的命名提示词档案；每份档案包含名称和 Markdown 正文，每个工具同时最多一份生效。
- Claude 生效目标为 `$CLAUDE_CONFIG_DIR/CLAUDE.md`（默认 `~/.claude/CLAUDE.md`）；Codex 生效目标为 `$CODEX_HOME/AGENTS.md`（默认 `~/.codex/AGENTS.md`）。
- 用户可以新建、编辑、重命名、删除和切换档案。
- 首次发现目标文件已有内容时，将原内容导入为当前档案并保持内容不变，不直接覆盖。
- 检测到 Codex `AGENTS.override.md` 等更高优先级文件时明确提示当前档案可能被遮蔽。
- 应用前展示目标文件和差异；写入失败时原文件保持可恢复。界面提示新提示词通常从新的 Claude/Codex 会话开始生效。

### R3. MCP 中央列表与分配

- 提供统一 MCP 列表，支持新增、编辑、删除、启停、内容查看和逐目标同步状态。
- MVP 表单支持 `stdio` 与 `streamable_http`；结构化保存 command、args、url、headers、env 等已知字段，并保留导入配置中无法统一抽象的工具扩展字段。
- 每个 MCP 可分配到 Claude、Codex 或二者的全局配置：Claude 用户级 MCP 按官方明确路径位于 `$HOME/.claude.json`，Codex 位于 `$CODEX_HOME/config.toml`。
- 项目级 MCP 写入用户登记的项目根：Claude 使用 `.mcp.json`，Codex 使用受信任项目的 `.codex/config.toml`。
- 全局分配始终保留，项目分配只追加。项目选择器把已全局分配项显示为“全局继承”且不可禁用或重复选择。
- 中央 MCP 名称在 MVP 内唯一；若项目原生配置已存在与全局项同名的外部条目，阻止应用并提示冲突，避免工具原生覆盖规则破坏“只追加”语义。
- 更新、重命名或删除时，只清理仍与本应用基线匹配的旧受管条目，不按名称盲删外部配置。

### R4. Skills 中央列表与分配

- MVP 只扫描或导入已有本地目录；目录必须包含合法 `SKILL.md`。不提供 Git、ZIP、市场安装、在线更新或版本管理。
- 导入时把 Skill 内容复制到应用私有中央库，保留原始来源目录不变；中央库记录内容 hash 和元数据。
- 提供列表、内容预览、移出中央库、全局分配、项目分配和逐目标同步状态。
- 全局目标：Claude 为 `$CLAUDE_CONFIG_DIR/skills`（默认 `~/.claude/skills`），Codex 为 `$HOME/.agents/skills`；项目目标：Claude 为 `.claude/skills`，Codex 为 `.agents/skills`。Codex 用户 Skills 明确不随 `CODEX_HOME` 迁移。
- 所有目标使用指向中央库的目录符号链接，不复制 Skill 内容到工具或项目目录。
- 全局分配始终保留，项目分配只追加。已全局分配项显示为“全局继承”且不可禁用或重复选择。
- 同名外部 Skill、普通目录占位、断裂链接、链接逃逸或更高优先级遮蔽均视为警告或冲突，不得递归删除未知目录。
- 同步状态至少区分：已同步、内容已变化、目标缺失、外部修改、冲突、受策略阻止和失败。

### R5. 项目管理

- 用户可以登记、重新扫描和移除本地项目目录；应用显示路径有效性、Git 仓库状态和 Claude/Codex 配置状态。
- 用户登记的目录就是项目根。项目详情分别展示 Claude/Codex 的 MCP 与 Skills 追加选择，并持续显示全局继承项。
- 项目级配置只保证当前 Mac 生效，不承诺可提交、打包或在其他机器复用。
- Codex 项目未受信任时不得声称配置已经生效；预览和结果必须显示阻止原因。
- 应用不修改项目 `.gitignore`。对应用新建且未被 Git 跟踪的目标，用户可在预览中选择写入本机 `.git/info/exclude`；已跟踪目标必须提示将产生工作区修改。

### R6. Preview、Apply、漂移与恢复

- 首次发现只分析和导入，不写入外部配置。
- 所有外部修改先生成统一预览，按目标文件或链接列出新增、更新、删除、不变、警告和冲突，并明确非受管内容将被保留。
- 预览记录完整文件 hash、受管投影 hash 和数据库版本；应用前重新验证。预览后目标变化时返回“预览已过期”，不得继续写入。
- 同一时刻只允许一个 Apply/Restore；数据库约束保证全库最多一个 `applying/restoring` run，预览令牌必须通过 SQLite 条件事务从 `previewed` 原子认领为 `applying`，重复提交或不同预览并发提交都不得产生竞态写入。
- 非受管字段外部变化可以确定性合并；受管字段外部变化、解析失败或无法判定所有权时阻止写入。
- 修改前创建私有快照；文件使用同目录临时文件、刷新落盘与原子替换，符号链接使用临时链接与原子重命名。
- 文件级写入不得留下截断或半写文件；多目标变更不是跨文件原子事务，任一目标失败时必须逆序恢复已写入目标。进程崩溃或恢复失败时保留 journal/快照，下次启动阻止新写入并显示恢复入口。
- 界面展示每个目标最后同步时间、状态、脱敏错误和可执行的恢复入口。

### R7. 本地数据与敏感信息

- SQLite 是结构化数据真源，启用迁移、外键和事务；无法统一的工具字段以受约束扩展数据保存，不以任意 JSON 代替全部领域模型。
- API Key 按用户决定以明文保存在本机数据库及工具必须读取的配置文件中；界面默认遮罩并明确这是 MVP 的安全取舍。
- API Key、MCP header/env 及扩展字段中识别出的秘密值不得进入日志、遥测、同步 journal、预览差异、错误详情、崩溃报告或版本控制建议文本；这些载体只保存脱敏值、路径、hash、状态和错误码。
- 快照可以包含秘密值，但只能位于应用私有数据目录，目录权限为当前用户专用，且不提供内容预览或导出。
- 应用数据目录必须为 `0700`；数据库、WAL/SHM、快照和其他可能含秘密的文件必须限制为当前用户读写，并在启动与发布检查中审计权限。
- 所有外部路径先 canonicalize/lstat；不得跟随未知入口链接写入中央库之外的位置。

### R8. 桌面端信息架构

- 左侧一级导航包含：总览、Claude、Codex、MCP、Skills、项目。
- Claude/Codex 页面分别提供渠道与全局提示词；MCP/Skills 是中央库页面；项目详情提供两工具的项目追加选择。
- 总览展示当前渠道、当前提示词、全局分配数量、项目数、最近同步和待处理冲突。
- 空状态只有一个明确下一步；解析失败、权限不足、工具未安装、策略阻止、漂移和断链均有独立状态，不统一显示为“失败”。

## Acceptance Criteria

- [ ] **AC1**：应用可在 macOS 13+ 安装启动，并按目标矩阵发现默认路径与 `CLAUDE_CONFIG_DIR`/`CODEX_HOME` 覆盖路径；Codex 用户 Skills 仍解析到 `$HOME/.agents/skills`。若非默认 Claude 配置目录下的用户 MCP 实际位置无法从当前安装版本安全确认，则阻止该目标写入并说明原因。
- [ ] **AC2**：Claude/Codex Provider 档案彼此独立且各自最多一个生效；切换后非 Provider 字段保持不变，旧受管字段正确清理，密钥默认遮罩且日志不可检索到明文。
- [ ] **AC3**：已有 Claude/Codex 全局提示词首次接管时被无损导入；用户可维护多份命名档案并切换，失败时可恢复原文件。
- [ ] **AC4**：用户可维护 MCP，并分别分配到 Claude/Codex 全局目标；原生配置中的非受管条目和未知字段保持不变。
- [ ] **AC5**：用户可导入含 `SKILL.md` 的本地 Skill；中央库使用副本，工具全局目标使用指向中央库的符号链接，原始来源目录不被修改。
- [ ] **AC6**：用户可登记项目，为 Claude/Codex 追加 MCP 与 Skills；应用只写官方项目路径，全局项显示为继承且不存在项目禁用入口。
- [ ] **AC7**：项目选择不能创建与全局同名的应用内冲突；已存在的外部同名项会阻止应用并显示原因。
- [ ] **AC8**：项目 Skill 是指向中央库的符号链接；普通目录、断链、链接逃逸和未知目标不会被静默覆盖或递归删除。
- [ ] **AC9**：预览准确列出新增、更新、删除、不变、警告和冲突；预览后的外部变化会使应用返回“预览已过期”。
- [ ] **AC10**：非受管外部变化可以安全保留，受管字段变化或解析失败会阻止覆盖。
- [ ] **AC11**：任一目标都不会留下截断或半写文件；多目标写入失败后，已写目标成功逆序回滚，或提供可定位的私有快照与人工恢复信息；崩溃遗留 run 会在下次启动阻止新写入并进入恢复流程。
- [ ] **AC12**：应用不修改 `.gitignore`；写入已跟踪项目配置前明确警告，写入 `.git/info/exclude` 仅在用户于预览中确认后发生。
- [ ] **AC13**：Codex 未受信任项目、Claude 管理策略阻止、权限不足和工具未安装均显示为不同的受阻状态，不误报为已同步。
- [ ] **AC14**：MCP/Skills 全局与项目配置完成一条端到端流程：中央库变更 → 目标预览 → 应用 → 原生文件/链接验证 → 漂移检测 → 快照恢复。

## Out of Scope for MVP

- Windows/Linux 安装包、路径适配和兼容性测试。
- Claude/Codex 会话历史、启动器、托盘和常驻后台监听。
- SSH、WSL、远程主机、WebDAV、云同步、账号与团队协作。
- Claude/Codex 之外工具的正式支持。
- MCP 商店、Skills 市场、Git/ZIP/远程 Skills 安装、在线更新与版本管理。
- 项目配置的提交、打包、导出或跨机器复用。
- 用户配置导入导出和用户级备份；内部回滚快照除外。
- 本地 API、渠道代理/中转服务及其进程管理。
- macOS 钥匙串、外部密钥 helper 和环境变量密钥引用。
- 项目级禁用全局 MCP/Skills、Copy 模式、Preset、标签和批量跨项目操作。

## Technical Notes

- 计划采用 Tauri 2 + React + TypeScript + Rust + SQLite；最终边界、数据模型和验证见 `design.md` 与 `implement.md`。
- 全局提示词是工具加载的用户指令文件，不替换 Claude/Codex 内部系统提示词。
- 本任务保持为一个实现任务，以共享同步内核和端到端验收为边界；执行计划按可独立验证的阶段设置检查点，不额外创建子任务。
