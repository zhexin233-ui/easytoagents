# 调整 MCP 与 Skill 中央列表布局及平台图标

## Goal

让 MCP 与 Skills 的中央列表在信息密度较高时可切换为每行三项的卡片网格，并用 Claude、Codex 品牌图标替代冗长的全局分配按钮文字，使列表更紧凑且平台状态更易识别。

## Background

- MCP 中央列表当前位于 `src/features/mcp/mcp-page.tsx`，仅以单列 `space-y-3` 展示。
- Skills 中央列表当前位于 `src/features/skills/skills-page.tsx`，同样仅以单列 `space-y-3` 展示。
- 两个页面的全局分配入口目前显示“Claude/Codex 全局已分配/未分配”，并通过按钮 variant 区分状态。
- 仓库当前没有通用图标依赖或可复用的 Claude/Codex 图标组件。
- 全局分配状态仍以 DTO 的 `globalTools` 为唯一数据源；本任务不改变后端协议或 mutation 行为。

## Requirements

### R1：中央列表布局切换

- MCP 与 Skills 的“中央列表”标题区都提供单列与三列网格两种显示方式的切换控件。
- 单列保持现有卡片排列；三列模式在空间充足时每行显示三个卡片，较窄视口允许响应式降为两列或一列，避免横向溢出。
- 三列模式参考用户提供的界面：卡片采用紧凑的“主体内容 + 底部分隔操作栏”结构，标题、摘要和主要状态位于主体，平台分配图标集中在底部操作栏右侧；各卡片等高，长文本截断或安全换行，不得把完整单列内容机械挤入窄卡片。
- 三列模式只调整信息层级与视觉密度，不移除编辑、启停、删除、预览或分配等既有操作能力。
- 当前显示模式是页面级临时 UI 状态，不写入后端，也不新增持久化存储。
- 默认继续使用现有单列布局，避免改变用户首次进入页面时的展示习惯。
- 切换控件使用原生按钮语义，具有可查询的无障碍名称，并通过 `aria-pressed` 或等效语义表达当前模式。

### R2：平台分配图标

- MCP 与 Skills 卡片中的 Claude 全局分配按钮改为 Claude 图标，Codex 全局分配按钮改为 Codex 图标。
- 图标按钮保留现有点击、pending 禁用，以及 Skills 非 `ready` 项不可新增分配但可取消已有分配的行为。
- 已分配状态使用正常、醒目的图标；未分配状态使用明显变暗的图标。
- 图标按钮必须保留完整的可访问名称，明确平台及“全局已分配/未分配”状态，并暴露 pressed 状态；不能只依赖颜色传达状态。
- Claude 与 Codex 图标必须分别使用 Anthropic/OpenAI 官方发布的原始品牌资产，不允许手绘、近似重建或由 AI 生成路径。
- 官方资产下载后随前端本地打包，保留来源说明，不在运行时依赖远程 CDN，也不引入新的运行时图标依赖。

### R3：共享与一致性

- MCP 和 Skills 使用同一个平台分配图标按钮组件或等价的共享实现，避免两页重复品牌图标及状态样式。
- 两页的布局切换交互、图标尺寸、激活/未激活视觉规则保持一致。

## Acceptance Criteria

- [ ] MCP 中央列表可在单列和三列模式间切换；宽屏三列模式每行最多显示三个卡片，窄屏不横向溢出。
- [ ] Skills 中央列表可在单列和三列模式间切换；宽屏三列模式每行最多显示三个卡片，窄屏不横向溢出。
- [ ] 三列卡片与参考图的信息层级一致：紧凑主体、底部分隔操作栏、平台图标右对齐、等高排列，长内容不会撑破卡片。
- [ ] 两页默认仍为单列，切换只在当前页面生命周期内生效。
- [ ] Claude/Codex 全局分配入口显示对应官方平台图标，不再显示原来的长按钮文案；仓库中没有手绘近似品牌 SVG。
- [ ] 已分配图标醒目，未分配图标变暗；按钮的 accessible name 与 pressed 状态仍能区分平台和分配状态。
- [ ] 点击图标后仍提交与当前实现完全相同的 MCP 或 Skill 全局分配 payload，并正确刷新列表。
- [ ] pending、disabled 及无效 Skill 的恢复性取消分配行为无回归。
- [ ] MCP 与 Skills 相关组件测试覆盖默认布局、布局切换、图标按钮无障碍语义和分配 mutation。
- [ ] `pnpm` 前端格式、lint、类型检查和相关测试通过。

## Out of Scope

- 不修改 MCP、Skills 或全局目标状态的后端数据结构、命令和同步流程。
- 不持久化用户的布局偏好，也不在 MCP 与 Skills 页面之间同步该偏好。
- 不调整项目级分配、全局目标状态卡片、CRUD 表单或内容预览交互。
- 不新增完整的通用图标库。
- 不照搬参考图的暗色主题、其他平台图标或无关功能；仅采用其卡片层级、底部操作栏和激活/未激活平台状态表达。

## Key Decisions

- 此任务按轻量前端任务处理，仅维护 PRD，不新增 `design.md` 与 `implement.md`。
- 布局切换默认值为单列；三列是用户主动选择的紧凑视图。
- 图标按钮采用共享组件并导入本地官方品牌资产，保留 `aria-label`、`aria-pressed` 和 `title`，兼顾紧凑视觉与无障碍状态表达。
- 参考图只决定三列卡片的信息层级与图标状态排布，不改变应用现有亮色视觉体系。

## Risks and Deferred Items

- 三列模式会压缩卡片宽度；实现时需重点检查 MCP 长入口、JSON 预览和 Skill 路径的换行/滚动表现。
- 官方品牌资产必须保留可追溯来源；若官方仅提供公司级图标，则 Claude 使用 Anthropic press kit 的 Claude 标识，Codex 使用 OpenAI Codex 官方页面采用的 OpenAI Blossom 标识。
