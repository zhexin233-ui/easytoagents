# 技术设计

## 边界与数据流
新增 GitHub 下载模块和独立 `import_github_skill` RPC，输入仅 URL，返回现有 SkillDto。Rust/Specta 生成前端绑定。前端独立弹窗沿用本地目录弹窗的模态焦点、锁和刷新方式。

网络操作在后台执行，下载阶段不持有数据库锁。URL 解析 → 将 ref 解析到 commit SHA → 读取指定子树 → 下载资源到私有临时目录 → 复用目录校验与中央入库 → 清理下载目录 → 返回结果。不得把临时目录存成可长期展示的来源；入库来源记录规范化 GitHub URL，检查现有 source_path 消费者的兼容性。

## 下载方案
新增 Rust HTTP 客户端（优先 reqwest，选择兼容项目工具链的版本）。通过固定 GitHub API 获取 ref/树元数据，以固定 SHA 从 GitHub 获取文件；不依赖本机 Git、不下载整个仓库归档。递归遍历仅指定子树，拒绝截断的树响应、symlink 和 submodule。ref 含斜线时按最长有效前缀解析，设置候选请求数上限并报告无法解析。

只允许 HTTPS github.com 的 tree 目录链接；拒绝凭据、非标准端口、不安全路径段。逐段正确解码与重新编码，不从远端响应接受任意下载主机。HTTP 设置 User-Agent、连接和整体超时、响应大小和请求数上限，拒绝异常状态。保留 HTTP(S)/ALL_PROXY 环境支持，不写永久代理配置；GUI 系统代理行为在实机验证时记录。

下载和已有目录校验共用限额：4096 文件、深度 32、单文件 8 MiB、SKILL.md 512 KiB、总文件内容 32 MiB、相对路径 1024 字节；元数据另设有限响应预算。使用每次独立的私有 staging 和 RAII 清理，不执行脚本。

## 入库、错误与兼容
复用 prepare/finalize 和冲突校验，保持排他落盘。新增下载入口须核验 SQL 提交失败与结果不确定时的处理，不能盲删可能已提交副本。错误保持固定中文文案，不透出响应正文或代理凭据；区分无效链接、未找到、限流与下载失败。

既有本地导入与全局发现流程保持原合同，不迁移历史数据。GitHub 来源不是可供本地 Path 读取的路径，所有消费点应核验。UI 必须区分提交成功与随后刷新失败。

## 取舍与风险
GitHub API 免登录有限流，提供明确错误与重试提示；不加入 Token 配置。逐文件下载减少大仓库开销但请求更多，限制总请求数与时间。远端 fixture 可能变化，自动化测试使用固定本地模拟数据，两个真实示例另外做集成验证。

## 回滚
撤回新入口、RPC 和下载模块即可；已成功创建的中央技能沿用既有格式，不需要数据回滚。
