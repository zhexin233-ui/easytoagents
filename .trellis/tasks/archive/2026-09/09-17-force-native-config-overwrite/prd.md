# 原生配置变更直接强制覆盖

## Goal

让应用完整负责中央配置到原生配置的同步：任何已接受、且会改变当前有效配置的用户操作，都在同一操作链自动完成 Preview → Apply；受管内容差异由中央意图直接覆盖，不再弹出确认页、要求额外切换，或把用户赶到文件夹手工处理。

## Background

- 当前 `direct` 模式只自动应用无冲突 Preview；受管内容漂移仍回退到“确认原生配置变更”，后端也拒绝消费 conflict Preview。
- Provider 编辑当前已选渠道只更新数据库；只有再次切换渠道才触发同步，因此用户必须切走再切回。
- Prompt、MCP、Skill、Hook、Agent 的自动同步分散在页面中，大量入口仅在 `direct` 模式触发；Hooks 甚至存在添加会同步、移除不同步的非对称路径。
- MCP、Hook、Agent 的 DTO 只暴露全局分配，中央编辑/启停无法发现 project-only assignments，导致项目原生配置长期保留旧内容。
- 持久化 Preview 同时承担 descriptor、ownership、磁盘 hash、行版本、单写者、快照、journal 和回滚证据；它不是 UI 确认页，必须保留。
- 用户明确接受这是破坏性行为变更，并确认范围包括常规同步、项目原生资源禁用/恢复、首次 Skill 正式目录接管，以及 Provider、Prompt、MCP、Skill、Hook、Agent 的全部有效配置变更。

## Requirements

### R1. 统一直接执行

- 删除常规配置同步、项目原生资源禁用/恢复、首次 Skill 正式目录接管的二次确认步骤。
- 用户完成具有明确意图的主操作后，应用必须内部生成并立即消费持久化 Preview，不再要求点击“应用这份预览”。
- 删除 `preview_confirm` / `direct` 双模式及设置页开关；旧持久化设置可以作为无害历史数据保留，但不得改变新行为。
- 操作不得再以“请到文件夹手工处理”作为正常终点。真实失败必须在应用内明确呈现，并允许从应用内重试同步。

### R2. 所有有效中央意图变更立即同步

- 统一覆盖 Provider 渠道、Prompt、MCP、Skill、Hook、Agent 的新增、编辑、删除、启用/禁用、当前选择切换、全局分配和项目分配。
- 只有已接受且实际影响当前有效投影的操作才产生原生写入；未分配的新建/复制导入不写原生文件，未改变目标投影的 Preview 以 no-op 结束。
- 编辑当前已选 Provider 后必须立即同步；Pi 等多 Provider 投影按实际参与规则同步，不能只看单个 `isActive` 标志。
- 中央资源编辑/启停必须覆盖其全部全局分配和显式项目分配；只通过全局继承读取资源的项目不产生冗余项目文件写入。
- 分配类操作按精确 `(artifact kind, tool, projectId|null)` 范围同步；多范围稳定去重并串行执行，避免同一路径并发写入。
- 受影响范围由后端依据变更前后 assignment/selection 和 managed state 计算并返回，前端不得继续依赖只含全局分配的旧 DTO 猜测范围。
- 删除仍遵守应用内现有引用约束：若分配未解除而删除被后端拒绝，则中央意图未改变且不触发同步；允许删除当前 Provider/Prompt 等有效资源时，必须先保留删除前范围并同步清理对应原生投影。

### R3. 强制覆盖的安全边界

- “强制覆盖”只改变可安全读取、目标类型合法且 ownership 明确的受管内容漂移。
- 当应用扫描到其他程序已修改原生文件时，不把该变化当成只能失败的并发冲突；应用必须在界面中提供两种可直接完成的动作：采纳原生变化到中央配置，或以当前中央配置覆盖原生变化。
- 中央配置操作触发同步时，默认直接以中央配置覆盖已扫描到的外部变化，不再弹出选择或确认；只有后台/被动扫描独立发现外部变化时才保留双方内容并等待用户在应用内选择方向。
- 采纳原生变化必须遵守资源 ownership：只更新应用管理的 Provider、Prompt、MCP、Skill、Hook、Agent 投影，不得把未知字段误收为中央配置；覆盖动作继续走持久化 Preview → Apply、快照和回滚。
- “采纳原生更改”必须真正更新中央实体与基线，不能使用只刷新 baseline 的 readopt 冒充；下一次中央同步不得把刚采纳的内容改回去。
- 可由既有 managed identity 唯一配对且能无损映射的变化直接采纳；原生重命名、新增条目、Hook 匿名项或包含未建模字段等无法唯一/无损映射的情况，在应用内进入匹配或导入流程，不允许静默猜测。
- 外部变化按使用时机扫描：进入相关页面、切回应用、环境刷新及显式重新扫描时检测；本任务不新增常驻文件 watcher。
- `Selectors` 仅覆盖受管字段并保留未知字段/表；`WholeDocument` 覆盖整份受管文档；`SymlinkNames` 只替换用户选择或分配的同名入口。
- 解析失败、权限失败、策略/信任阻断、unsupported、未知或危险路径类型、路径逃逸、恢复身份不匹配等真实安全/I/O 错误继续 fail closed。
- Preview → Apply 必须继续绑定 descriptor、ownership、row version 和生成时磁盘 hash；Preview 后发生变化时最多自动重新 Preview 一次，不得盲写未观察到的新内容。
- 保留写前快照、journal、原子 mutation、自动回滚和历史恢复能力。

### R4. 特殊流程

- 首次 Skill 正式目录接管保留检测、条目选择和显式“接管所选项”主操作；随后直接 Apply，复用 `.takeover` 隔离、`directory_tree` 快照和回滚，禁止递归强删目录或跟随删除外部链接目标。
- 项目原生资源仍由用户点击“禁用”或“恢复”表达意图；Preview 后直接 Apply。恢复目标被未知入口占用或身份变化时继续阻断。
- 仅服务旧冲突恢复的 readopt、`readoptAvailable` 和“按原生内容接管渠道档案”从同步链移除；本任务不新增反向导入替代入口。

## Acceptance Criteria

- [ ] 原生配置已存在且受管内容不同，用户操作后无需二次确认即可覆盖；UI 不再展示“确认原生配置变更”或要求进入文件夹手工处理。
- [ ] 编辑当前已选 Provider 后，同一操作链完成 Preview → Apply，原生配置立即反映新值，无需切走再切回。
- [ ] Provider、Prompt、MCP、Skill、Hook、Agent 的全部有效变更入口均遵守同一自动同步规则；未分配新建/导入不产生原生写入。
- [ ] 中央编辑/启停可同步全部全局与显式项目分配；测试覆盖 project-only MCP、Hook、Agent 等旧遗漏，且不改写无关目标文件。
- [ ] 全局/项目 assignment 变更自动同步精确 scope；Hook 添加、事件切换和移除不存在非对称行为。
- [ ] 已接受的多 scope 操作等待所有 scope 完成或失败后才给出最终结果；scope 稳定去重、串行执行，并精确消费各自 `previewId`。
- [ ] 设置页和生成 DTO 不再包含 apply mode；旧 `apply_mode` 数据不影响行为。
- [ ] Preview 后并发变化只自动重建一次；第二次 stale、解析/权限/路径/策略/信任错误停止写入并在应用内反馈、可重试。
- [ ] 扫描检测到可安全解析的外部修改时，用户可在应用内选择“采纳原生更改”或“以中央配置覆盖”，两条路径都无需进入文件夹手工处理。
- [ ] 采纳后中央实体内容、row version、managed item 与 target baseline 在一致的事务/文件复制边界内更新；随后重新扫描为 in-sync。
- [ ] Provider、Prompt、MCP、Skill、Hook、Agent 均覆盖可唯一映射的采纳路径；无法唯一映射时提供应用内匹配/导入入口和明确原因，不直接禁用为“请手工处理”。
- [ ] 进入相关页面、切回应用、环境刷新或显式重新扫描后能发现六类资源的外部受管变化；应用后台静置期间不要求实时监听。
- [ ] 被覆盖内容有可恢复快照；写入中途失败自动回滚，回滚失败保留恢复证据。
- [ ] selector 未受管内容、未知 Skill 兄弟和外部 symlink 真实目标保持不变。
- [ ] Skill 接管所选项后安全完成目录/链接接管且无二次确认；项目原生资源禁用/恢复也自动消费精确 Preview。
- [ ] 旧确认/readopt 分支、失效文案、页面级触发猜测和对应旧测试被删除或改写，前后端规范一致。

## Out of Scope

- 取消底层快照、journal、自动回滚或历史恢复能力。
- 放宽历史恢复的目标身份校验，或删除独立历史恢复流程。
- 将强制覆盖扩展到应用不拥有的字段、任意用户文件、未知 Skill 兄弟或外部链接真实目标。
- 将无法解析的 selector 文档当成 whole-document 重建并丢弃未知内容。
- 未经用户选择，自动接管未纳管的任意 Skill 条目。
- 绕过应用内 assignment/引用约束，级联强删仍被有效引用的中央资源。

## Notes

- 这是有意的破坏性产品行为变更；升级后旧 `preview_confirm` 用户也会直接执行原生写入。
- “全部都一样”指统一的结果合同，不要求每个无投影变化的操作执行冗余文件写入；no-op Preview 仍是正确完成。

- 用户已确认：中央操作默认覆盖；被动检测不自动修改任一侧，只提供应用内“采纳原生更改 / 以中央配置覆盖”双向操作。
- 用户已确认：采用按使用时机扫描，不新增常驻文件 watcher。
