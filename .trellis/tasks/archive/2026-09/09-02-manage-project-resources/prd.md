# 管理项目级 Skill、MCP 与提示词

## Goal

让用户在登记项目后统一看见并安全管理项目原本自带的 Skill、MCP 与提示词；默认不改变这些资源，用户可显式临时禁用单个资源，并在不覆盖外部变化的前提下恢复。

## Background

- 当前“导入项目”实际是登记项目：登记时扫描目标状态，但不会写入项目文件。
- 当前项目详情页只管理中央资源对项目的追加分配，尚未逐项展示项目原生资源。
- 用户明确选择“只读识别、显式操作”，不接受登记时自动接管或改写。

## Confirmed Facts

- 项目级支持矩阵为：Claude、Codex、Cursor 的 MCP 与 Skill，以及 Claude、Codex 的提示词；Cursor 项目提示词不受支持。
- 现有同步合同要求原生写入经过持久化预览与精确 Apply，并使用哈希、CAS、原子写入、快照和失败回滚。
- 当前没有“项目原生单资源临时禁用并恢复”的统一命令、持久化模型或端到端测试。
- MCP 的逻辑资源单位是单个 server 条目，Skill 是正式项目技能根的直属入口，Prompt 是整个项目提示词文件。

## Requirements

- R1：登记和重新扫描项目时，发现现有适配器支持的项目级原生 Skill、MCP 与 Prompt，不改写项目内容。
- R2：项目详情页按平台与资源类型逐项展示原生资源，并与中央追加/托管资源明确分区。
- R3：每个原生资源展示安全名称、类型、来源和状态；MCP 凭据或私有配置不得进入普通 DTO、错误、日志或界面。
- R4：用户可对单个处于活动状态的原生资源发起禁用预览；即使启用“直接应用”偏好，也必须审阅并确认这类预览。
- R5：确认禁用后，目标工具不再从原生生效位置发现该资源，同时应用保留可验证、可恢复的私有副本。
- R6：用户可对单个已禁用资源发起恢复预览；恢复成功后路径、内容、适用的文件 mode 或链接文本符合禁用前状态。
- R7：MCP 禁用/恢复只修改目标条目并保留未知兄弟；Skill 只处理目标直属入口且不修改外部链接目标；Prompt 按整文件处理。
- R8：禁用状态、恢复材料和冲突状态跨重启、重新扫描及项目详情刷新持续可识别。
- R9：预览过期、外部修改、同名/路径占用、权限变化、并发写入或回滚失败时拒绝危险操作，并保留恢复材料。
- R10：仍有原生资源处于禁用状态时，不允许移除项目登记或删除其必要快照；用户须先恢复资源。

## Out of Scope

- 登记时自动导入中央库、自动创建 assignment 或自动接管 ownership。
- 在本功能中编辑、重命名、批量禁用或批量恢复资源内容。
- Cursor 项目级提示词、全局资源以及适配器未声明支持的路径或格式。
- 将项目原生资源与中央资源自动去重、合并或同步。

## Acceptance Criteria

- AC1（R1-R3）：登记包含项目级资源的 fixture 后，详情页在正确的平台/类型组合下列出每个原生资源；登记前后项目原生字节、目录树和链接文本一致。
- AC2（R2-R3）：项目原生与中央追加分区、来源和状态清晰可辨；任何非私有载体均不包含 fixture MCP secret。
- AC3（R4-R5）：用户选择一个原生 MCP、Skill 或 Prompt 后先看到持久化预览；确认后仅目标资源失效，未选择资源的语义值保持不变，TOML 目标之外的注释保持不变。
- AC4（R5-R8）：重启或重新扫描后，已禁用资源仍显示“已禁用”并提供恢复入口。
- AC5（R6-R7）：恢复 MCP 保留当前无关条目，恢复 Skill 还原完整树或原链接文本，恢复 Prompt 还原原始文件字节与权限。
- AC6（R9）：目标同名/路径被重新占用、目标内容变化、预览过期或存在活动 writer 时，操作以稳定错误拒绝且不覆盖外部内容。
- AC7（R9）：任一文件或数据库步骤失败时自动回滚；无法安全回滚时进入 rollback_failed，保留快照并阻止后续 writer。
- AC8（R10）：存在已禁用项目原生资源时，移除项目登记或删除引用快照会被阻止并给出可行动提示。
- AC9：Rust 迁移、服务与同步测试、前端交互测试、生成绑定检查以及 pnpm check 全部通过。

## Key Decisions

- 项目原生资源采用“只读识别、显式操作”模型。
- “临时禁用”跨重启和重新扫描持续生效，直到用户显式恢复；扫描不会自动恢复。
- 原生资源拥有独立持久化身份与状态，不借用中央资源 ownership 表达来源。
- 所有原生写入统一经过 Preview → 显式 Apply；恢复冲突时保留私有副本，不覆盖目标。
