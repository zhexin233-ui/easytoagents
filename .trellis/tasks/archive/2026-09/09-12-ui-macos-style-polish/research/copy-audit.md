# Research: 页面文案盘点与冗余评估（copy-audit）

- **Query**: 盘点 `src/features/**/*.tsx`、`src/components/*.tsx`、`src/app/*.tsx` 中所有静态展示文案，评估保留/精简/删除
- **Scope**: internal
- **Date**: 2026-09-12

## 类型代号

| 代号 | 含义 |
|---|---|
| A | 页面级描述（标题下的段落、eyebrow 小标） |
| B | 区块级说明（section/卡片标题下的说明） |
| C | 表单字段 help text / 复选框说明 |
| D | 空状态文案 |
| E | 错误 / 阻塞 / 状态提示文案 |

判断栏：**保留** / **精简** / **删除**。仅评估静态展示文案；按钮标签、aria-label、toast 消息、代码注释不计入（但在"文案分布"一节说明）。

## 总结

全站共盘点 291 条静态展示文案（22 个文件/对话框组），建议删除 19 条、精简 79 条、保留 193 条。可删除项集中在两类：一是每个页面 h1 上方的 eyebrow 小标（11 处），与标题或侧栏导航重复；二是页面级描述段落中反复出现的"只更新中央意图，原生写入需经持久化预览"这一通用约束（11 处以上），建议收敛到一处（如首次接管向导或设置对话框）后其余删除。可精简项主要是：空状态文案（5 处同构，可统一为"尚无 X。可新增或导入。"）、表单对话框 description（4 处同构）、以及带内部术语（capability probe、DTO、CRUD、journal、安装探针、状态码）的阻塞/状态文案。必须保留的是脱敏说明（MCP 敏感字段、Hook 命令凭据、API Key 遮罩、env 疑似凭据不纳管）、只读/继承约束、会修改哪些文件的说明（官方登录的 settings.json / config.toml / auth.json）、破坏性操作确认、以及所有加载/错误/阻塞状态。文案最密集且最值得优先处理的是首次接管向导、设置对话框（含全站最长的 170 字"直接应用"说明）与 Skills 导入对话框。项目无 i18n 框架，文案全部硬编码，仅 `provider-text.ts`、`global-target-status-ui.ts`、`sync-status-badge.tsx`、`hook-events.ts` 等少数文件做了就近集中，页面级说明段落均内联在 JSX 中。
