# 持久化中央列表列数选择

## Goal

让用户离开并重新进入带有中央列表的页面后，仍保留此前选择的单列或三列布局，避免每次切换顶部标签都恢复为默认单列。

## Background

- MCP 页的布局状态目前由 `src/features/mcp/mcp-page.tsx:90` 的本地 `useState` 保存，默认值为 `"list"`；切换路由后页面卸载并重建，状态因此丢失。
- Skills 页在 `src/features/skills/skills-page.tsx:53` 使用同样的本地状态与默认值，也存在相同的生命周期限制。
- 共享布局类型仅允许 `"list" | "grid"`，定义于 `src/components/central-list-layout.tsx:6`。
- 项目已有原生 `localStorage`、版本化 key、异常回退的偏好持久化模式，见 `src/features/onboarding/onboarding-wizard.tsx:20` 与 `src/features/onboarding/onboarding-wizard.tsx:572`。
- 上一任务明确把布局偏好持久化排除在范围外；本任务将有针对性地补上这一能力，不改变列表视觉或业务数据协议。

## Requirements

### R1：记住布局选择

- 用户选择单列或三列后，离开当前页面并通过顶部标签返回时，页面恢复到最近一次有效选择。
- 首次使用或没有有效持久化值时，继续默认显示单列。
- 持久化值只接受共享类型定义中的 `"list"` 与 `"grid"`；缺失、非法或读取失败时安全回退到单列。

### R2：保持现有行为

- 不改变单列、三列的视觉样式、响应式列数、切换按钮无障碍语义或卡片操作。
- 不修改 MCP、Skills 或全局目标状态的后端协议和业务数据。
- 使用项目现有前端偏好持久化方式，不引入新的状态管理依赖。

### R3：页面范围

- MCP 与 Skills 都必须支持布局选择持久化。
- 两个页面分别记忆各自最近一次选择；修改其中一页的布局不得改变另一页的选择。

## Acceptance Criteria

- [x] 在 MCP 页选择三列，切换到其他顶部标签后再返回 MCP，中央列表仍为三列。
- [x] 在 MCP 页选择单列，切换标签并返回后仍为单列。
- [x] Skills 页同样可在切换标签或重新挂载后恢复最近一次布局选择。
- [x] MCP 与 Skills 的布局偏好相互独立；在一页切换布局不会覆盖另一页的选择。
- [x] 没有持久化值或持久化值非法时，对应页面安全回退为单列且正常渲染。
- [x] 布局持久化不改变现有列表样式、切换控件语义和卡片业务操作。
- [x] 相关组件测试覆盖布局值的保存、页面重新挂载后的恢复以及非法值回退。
- [x] `pnpm` 的相关前端测试、类型检查和 lint 通过。

## Out of Scope

- 不把布局偏好写入后端或跨设备同步。
- 不调整中央列表的卡片设计、平台图标、CRUD 或分配操作。
- 不引入新的全局状态管理库。

## Key Decisions

- 本任务按轻量前端修复处理，只维护 PRD，不新增 `design.md` 或 `implement.md`。
- MCP 与 Skills 使用独立的版本化持久化 key，分别保存最近一次有效布局。
- 沿用项目现有原生 `localStorage` 模式；读取异常、值缺失或值不属于 `"list" | "grid"` 时回退到 `"list"`。
- 首次使用继续默认单列，不改变现有初始体验。

## Risks and Deferred Items

- `localStorage` 可能在受限环境中读写失败，实现必须吞掉存储异常并保持页面可用。
- 偏好仅保存在当前浏览器本地；跨设备、跨浏览器同步继续不在本任务范围内。
