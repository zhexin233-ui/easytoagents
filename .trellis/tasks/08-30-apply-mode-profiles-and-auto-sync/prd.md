# 直接应用模式接入 Provider/提示词并支持中央操作自动同步

## Goal

延续上一个任务（08-30-apply-mode-global-setting）的两点延伸：

1. 把「直接应用」开关接入 Claude/Codex 的 Provider 与提示词同步流程（此前明确排除）。
2. 修复用户反馈：直接应用模式下，在 Skills/MCP 中央列表做分配、启停等中央操作后，
   仍只更新中央配置并提示「点击直接应用全局同步写入」——预期这些操作自动触发同步并应用。

## Background

- 用户实际操作路径：开启直接应用后在 Skills 中央列表启用（分配）Skill，看到的仍是
  「全局分配已更新……点击直接应用全局同步写入工具目录」，需要再手动点一次同步。
- Provider/Prompt 面板的「预览渠道同步」「切换并预览」「预览提示词同步」目前始终走
  预览确认对话框；页面统一通过 `onPreview` 回调打开 ChangePreviewDialog。

## Requirements

- **R1 Provider/Prompt 接入开关**：ToolProfilesPage 读取 applyMode；预览无冲突时自动
  调用既有 `applyProfilePreview`，按钮文案切换为「直接应用」语义；冲突/错误回退对话框。
- **R2 中央操作自动同步**（仅直接应用模式，默认模式行为不变）：
  - Skills 中央列表：全局分配（启用/停用某工具）成功后自动生成该工具的全局预览并按
    R1 同样的规则应用或回退；
  - MCP 中央列表：全局分配切换后自动同步该工具；启用/停用后自动同步其已分配的所有工具；
  - 项目详情页：勾选/取消项目 MCP/Skill 追加后自动生成该项目预览并应用或回退；
  - 保存/删除/导入等其余操作保持手动同步（文案已正确指引）。
- **R3 文案与说明**：设置页说明更新（覆盖范围含 Provider/提示词、中央操作自动同步）；
  自动同步成功沿用现有「已应用 N 个目标」消息。
- **R4 安全性**：不新增任何写入路径；自动应用复用 `canAutoApplyPreview` 与既有 apply 命令。

## Non-goals

- 默认（预览确认）模式的任何行为变化。
- MCP 中央列表保存/删除、导入流程的自动同步（保持手动）。
- 批量操作的合并同步（逐操作同步即可，后端单写者串行）。

## Acceptance Criteria

- [ ] 直接应用模式下：Provider「直接应用渠道同步」「切换并直接应用」、提示词同步按钮
      无冲突预览时跳过对话框直接 Apply；冲突回退弹窗且 Apply 禁用。
- [ ] 直接应用模式下：Skills 分配切换、MCP 分配切换、MCP 启停、项目追加勾选后自动
      生成预览；无冲突时自动应用并展示结果消息；默认模式不触发自动同步。
- [ ] 设置页说明与实际行为一致。
- [ ] `pnpm check` 全绿。
